USSD Smart Payment Solution

Complete step-by-step guide for first-time setup, environment migration, and production deployment.

Last updated: 2026-07-10 (Docker Compose for local MySQL/MariaDB + Redis; XAMPP restore) App version: 1.0.0 Node.js: 18+ (CI uses 18) Also see root README.md for a short local-dev quick start.

§ Overview

USSD Smart Payment Solution (Stalynx Utility) is a billing and customer-management platform that connects M-Pesa payments, Zoho Books invoicing, TISP ISP provisioning, and Xtream Codes streaming. It exposes a REST API, serves a React admin dashboard at /admin, handles USSD payment flows, and runs background synchronization via BullMQ and Redis.

What this guide covers:

  • Fresh install on a new server or developer machine
  • Local databases via Docker Compose (yarn docker:up) — MySQL/MariaDB + Redis
  • Migrating from an older deployment (database, logs, environment), including XAMPP → Docker
  • All required services, environment variables, and external registrations
  • Production process layout (API, worker, optional Xtream scheduler)
  • Post-deploy verification and ongoing maintenance
  • Billing reconciliation UI, Zoho/TISP onboarding behaviour, and integration snapshot caching
Security: Never commit .env or real credentials. The template .env.dist contains example values — replace every secret before going live. Rotate JWT, M-Pesa, and Zoho tokens after migration.

§ Prerequisites

  • Node.js 18+ and Yarn (Corepack: corepack enable)
  • Docker Desktop (local development) — provides MariaDB + Redis via docker-compose.yml
  • MySQL 8+ / MariaDB 10.11+ (InnoDB, utf8mb4) — Docker for local; managed instance for production
  • Redis 6+ — required when SYNC_ENABLED=true (Docker for local)
  • Git for cloning and deployments
  • XAMPP MySQL is not required; prefer Docker. Use yarn db:restore-xampp only to migrate old XAMPP data once.
  • PM2 (production) — installed globally or per-user on the server
  • HTTPS reverse proxy (nginx, Caddy, or load balancer) for production M-Pesa/Zoho callbacks
  • Outbound network access to Safaricom Daraja, Zoho APIs, TISP host, Xtream panel
  • Safaricom Daraja app (sandbox or production) with STK Push and C2B URLs registered
  • Zoho Books organization with OAuth app (client ID, secret, refresh token)
  • TISP WebISPService endpoint reachability (HTTP — HTTPS may fail TLS on this host)
  • Xtream Codes panel API (port 25461) whitelisted for the billing server IP

TISP create payload behaviour (see api/controllers/tisp.controller.js):

  • BillingCycle is always sent as Monthly on INSERT — TISP renews monthly regardless of customer billing frequency (yearly/quarterly/custom).

3 MySQL / MariaDB setup

3.1 Local development (Docker — recommended)

Stop XAMPP MySQL if it is running and conflicting with ports. Then from the repo root:

yarn docker:up
# MariaDB listens on host port 3307 → container 3306
# Redis listens on host port 6379

yarn db:setup   # migrate + seed test users

Compose file: docker-compose.yml (image mariadb:10.11, volume mysql_data). Yarn helpers: yarn docker:up, yarn docker:down, yarn docker:logs.

Migrating from XAMPP: Old data under C:\xampp\mysql\data is not used automatically. After Docker is healthy, run yarn db:restore-xampp once to dump/import into the Docker database, then leave XAMPP MySQL stopped.

3.2 Production / managed MySQL

  1. Install MySQL 8+ or MariaDB and ensure the server is running (or use a managed instance).
  2. Create the database and a dedicated application user:
CREATE DATABASE ussd_smart_payment_solution CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER 'ussd_app'@'localhost' IDENTIFIED BY 'strong_password_here';
GRANT ALL PRIVILEGES ON ussd_smart_payment_solution.* TO 'ussd_app'@'localhost';
FLUSH PRIVILEGES;

Update .env with the new credentials (MYSQL_PORT is usually 3306). For remote DB hosts, adjust the host grant accordingly.

The connection pool enables multipleStatements: true so db/schema.sql and migration files can run multi-statement scripts in a single transaction.

4 Redis setup

4.1 Local development (Docker)

yarn docker:up starts Redis 7 Alpine on port 6379. Confirm with health check after the API is running:

curl http://localhost:4000/api/health
# expect redis: "connected"

If port 6379 is already taken by a host Redis install, Docker Redis may fail to bind — keep using the existing Redis and leave REDIS_HOST=127.0.0.1.

4.2 Production / standalone Redis

  1. Install Redis 6+ (redis-server) or use a managed Redis.
  2. Start Redis and confirm: redis-cli ping → PONG.
  3. Set REDIS_HOST, REDIS_PORT, and REDIS_PASSWORD in .env.

If Redis is unavailable, the API falls back to inline reconciliation scheduling but BullMQ workers will not run. Production requires Redis for reliable background sync.

10 Production deployment

10.1 Server preparation

  • Ubuntu/Debian server with Node 18+, MySQL, Redis, PM2
  • HTTPS certificate (Let's Encrypt) on public hostname
  • Firewall: allow 80/443 inbound; MySQL and Redis not publicly exposed
  • Create deploy user and app directory
  • Copy .env to server (never via git — protected during rsync)
  • Create writable logs/ directory

10.2 Reverse proxy (nginx example)

Terminate TLS at nginx and proxy to Node on PORT:

server {
    listen 443 ssl;
    server_name app.sulsolutions.biz;

    location / {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Socket.IO uses path /api/socket.io — the Upgrade headers above are required.

10.3 Build and start with PM2

cd /var/www/ussd_smart_payment_solution
yarn install
yarn build
yarn db:migrate          # run after deploys with new migrations
yarn db:seed             # first time only

# API process
pm2 start index.js --name ussd_smart_payment_solution

# Worker process (REQUIRED for background sync)
pm2 start workers/index.js --name ussd_worker

# Optional: Xtream daily scheduler
pm2 start jobs/xtreamDailyScheduler.js --name xtream_daily

pm2 save

12 External integrations setup

12.1 Zoho Books

  1. Create a Zoho API console application (Server-based application).
  2. Generate a refresh token with Books scopes.
  3. Set ZOHO_ORG_ID from Books → Settings → Organization Profile.
  4. Configure payment mode Mobile Money in Books → Settings → Payments.
  5. Set ZOHO_INVOICE_TAX_INCLUSIVE=true so M-Pesa amounts are not double-VAT'd.
  6. New customer billing (api/services/customerBillingOnboarding.js) when admin creates a customer:
    • Creates or links a Zoho contact using the customer’s full name as Bill To (C2B), not the customer number.
    • Creates one signup invoice with ad-hoc line items (package rate from dashboard; no Zoho catalog item_id required).
    • DSTV packages: adds a one-time DSTV one-time fee line (default KES 2,900 via ZOHO_DSTV_ONE_TIME_FEE) on the first invoice only — not a recurring monthly DSTV charge.
    • Recurring Zoho profile on signup is off by default (ZOHO_RECURRING_ON_SIGNUP=false) to avoid a second invoice.
    • Signup invoice email from this app is off by default (ZOHO_SIGNUP_INVOICE_EMAIL_ENABLED=false) — enable only if Zoho Books is not already emailing invoices.
    • Invoice numbers use per-customer sequences (migration 024); reference number remains the customer number for M-Pesa matching.
  7. M-Pesa paybill allocation uses the customer number as bill reference; Zoho contact lookup still uses customer number for existing contacts.
  8. Integration snapshots persist contact, invoices, payments, and recurring data in MySQL after API fetches — see Billing & reconciliation env.
  9. One-time: Set up the Zoho Invoice Paid webhook — see §13 Zoho webhook (one-time). Needed when customers pay invoices directly in Zoho Books (not via M-Pesa).

12.2 Safaricom Daraja (M-Pesa)

  1. Register app on Daraja portal (sandbox first, then production).
  2. Configure STK Push callback URL → https://YOUR_HOST/api/payment/callback
  3. Register C2B URLs:
    • Validation → https://YOUR_HOST/api/payment/validation
    • Confirmation → https://YOUR_HOST/api/payment/confirmation
  4. After deployment, admin can register C2B URLs via POST /api/payment/register (admin role).
  5. Switch TOKEN_URL, STK_PUSH_ENDPOINT, and credentials from sandbox to production URLs.

12.3 TISP WebISPService

  1. Confirm HTTP connectivity to TISP_CLIENT_STATUS_URL, TISP_SET_CLIENT_URL, ISP_PAYMENT_URL.
  2. Use HTTP only — HTTPS may fail TLS verification on the TISP host.
  3. Ensure TISP_SHORTCODE=000000 for new client inserts (using the M-Pesa paybill here causes ShortCode Missing errors).
  4. Every customer must have a building with a valid building name — TISP Router/Location fields use that name.
  5. BillingCycle is always Monthly on TISP create, even for yearly dashboard billing.
  6. Configure building IP rules in admin (Buildings) or legacy rules in api/config/buildingIpRules.js.
  7. On M-Pesa or Zoho webhook payment, SetISPPayment extends the customer’s TISP due date.

12.4 Xtream Codes

  1. Whitelist billing server IP on the Xtream panel.
  2. Set XTREAM_BASE_URL to API port 25461 (not admin UI 25500).
  3. Configure bouquets in config/xtream-sync.json.
  4. Test connectivity: yarn xtream:check
  5. Live API test (creates temp user): yarn xtream:test

12.5 Zoho Mail (billing gap emails)

  1. Obtain OAuth refresh token with ZohoMail.messages.CREATE scope.
  2. Set ZOHO_MAIL_ACCOUNT_ID and from-address variables.
  3. Used by Billing → Customer Communications module (manual reminder emails — separate from signup invoice email).

Zoho webhook setup (one-time)

Configure this once per environment (sandbox/production) so that when a customer pays an invoice directly in Zoho Books, the app extends their TISP subscription without polling the Zoho API. M-Pesa paybill and STK flows do not use this webhook — they use /api/payment/confirmation and /api/payment/callback instead.

After deploy, open admin Settings (/admin/settings) to copy the exact invoicePaid webhook URL and confirm secretConfigured: true once ZOHO_WEBHOOK_SECRET is set.
  1. Generate a long random string and set ZOHO_WEBHOOK_SECRET in .env on the server.
  2. Restart the API (pm2 reload ussd_smart_payment_solution) so the secret is loaded.
  3. In Zoho Books → Settings → Automation → Workflow Rules, create a rule:
    • Module: Invoices
    • When: Invoice Paid (or equivalent paid status)
    • Action: Webhook — POST the invoice JSON payload
  4. Webhook URL: https://YOUR_HOST/api/public/zoho/webhook (copy from Settings page in admin)
  5. Request header: x-zoho-webhook-secret: YOUR_SECRET (alternatives accepted: x-webhook-secret header or ?secret= query param)
  6. Test by marking a test invoice paid in Zoho Books and confirming TISP/subscription updates in the admin customer record.

Handler: api/controllers/public.controller.js → zohoWebhook. On success, completes pending upgrades or runs handleSubscriptionPaymentReceived for reconciliation.

21 Troubleshooting

Database connection fails

  • Verify MYSQL_* in .env and that the database exists
  • Local Docker: confirm MYSQL_PORT=3307, run yarn docker:up, then docker compose ps (MySQL should be healthy)
  • Check MySQL user host grants ('user'@'localhost' vs 'user'@'%')
  • Run yarn db:status for a connectivity test
  • Empty dashboard after switching to Docker is expected until you seed or run yarn db:restore-xampp

Redis disconnected in health check

  • Local: yarn docker:up (or start host Redis: redis-cli ping)
  • Check REDIS_HOST, password, firewall
  • If Docker Redis fails with “port already allocated”, another process owns 6379 — use that Redis instead
  • Worker process will exit if Redis is unreachable

Sync jobs not running

  • Confirm SYNC_ENABLED=true and worker PM2 process is up
  • Do not rely on WORKER_INLINE in production
  • Check admin Synchronization page and sync_jobs table

CORS / login issues

  • ADMIN_ORIGIN must exactly match the browser origin (scheme + host + port)
  • In production, access admin via HTTPS; cookies use secure: true

M-Pesa callbacks not received

  • URLs must be publicly reachable over HTTPS
  • Register URLs in Daraja portal and via POST /api/payment/register
  • Check nginx passes POST body and does not block Safaricom IPs

Zoho payments not applying

  • Verify ZOHO_PAYMENT_MODE exists in Books
  • M-Pesa bill reference must match the customer number; Zoho contact may be stored under the customer’s name — lookup uses customer number keys
  • Check logs/zoho-mpesa-payments.jsonl
  • Confirm ZOHO_INVOICE_TAX_INCLUSIVE=true
  • B2B customers are billed via agency contacts — agency invoice must exist before M-Pesa allocation

Zoho signup / duplicate invoices or emails

  • Default: one signup invoice only (ZOHO_RECURRING_ON_SIGNUP=false)
  • Default: app does not email signup invoices (ZOHO_SIGNUP_INVOICE_EMAIL_ENABLED=false) — use Zoho Books automation or enable the env var, not both
  • Migration 025 tracks zoho_signup_invoice_id and email-sent time to avoid resending
  • Retry billing from customer detail reuses an open signup invoice when one already exists

TISP errors

  • Use HTTP URLs, not HTTPS
  • ShortCode Missing — set TISP_SHORTCODE=000000 (not the M-Pesa paybill)
  • BillingCycle Missing / Router Missing — ensure building has a name; billing cycle is always sent as Monthly on create
  • Check timeouts: TISP_REQUEST_TIMEOUT_MS
  • Review logs/tisp-set-isp-payment.jsonl and customer tisp_sync_error on the profile

Zoho webhook not firing

  • Confirm ZOHO_WEBHOOK_SECRET is set and API was restarted after changing it
  • Check admin Settings → secretConfigured: true and copy the exact invoicePaid URL
  • Workflow must trigger on Invoice Paid and POST JSON (not email-only action)
  • Header must be x-zoho-webhook-secret matching your .env value
  • URL must be publicly reachable over HTTPS

Admin UI 404 in production

  • Run yarn build — admin/dist must exist
  • Access at /admin/ (trailing slash handled by Express)
